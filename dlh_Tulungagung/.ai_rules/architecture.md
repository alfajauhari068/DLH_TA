# AI Architecture Rules

## Purpose

This document defines the mandatory architectural rules for the DLH Tulungagung Website Re-Engineering Project.

These rules are absolute.

Every AI coding assistant (GitHub Copilot, Copilot Agent, Cursor, Claude Code, Gemini CLI, Cline, Continue, Windsurf, or any other AI) MUST follow these rules WITHOUT EXCEPTION.

If any instruction generated by the AI conflicts with these rules, these rules ALWAYS take precedence.

The AI MUST NEVER make architectural decisions independently.

Only the project owner may define or change the project architecture.

---

# General Principles

The AI MUST understand that this project is a long-term government information system.

Every implementation MUST prioritize:

- Maintainability
- Readability
- Scalability
- Security
- Performance
- Accessibility
- Consistency
- Reusability
- Predictability

The AI MUST NEVER prioritize writing fewer lines of code over writing maintainable code.

The AI MUST NEVER optimize by reducing architecture quality.

---

# Architecture Authority

The existing project architecture is the single source of truth.

The AI MUST NOT redesign any existing architecture.

The AI MUST NOT replace any architectural pattern.

The AI MUST NOT migrate the project to another architecture.

The AI MUST NOT introduce new architectural concepts without explicit user instruction.

---

# Project Scope

The project is a complete re-engineering of the DLH Tulungagung Website.

The AI MUST preserve every planned module.

The AI MUST NEVER remove features.

The AI MUST NEVER simplify features.

The AI MUST NEVER merge unrelated modules.

Every feature MUST remain modular.

---

# Folder Structure

The folder structure is fixed.

The AI MUST NEVER:

- rename folders
- move folders
- delete folders
- create alternative folder structures

unless explicitly instructed.

---

# File Structure

The AI MUST NEVER rename files.

The AI MUST NEVER move files.

The AI MUST NEVER duplicate files.

The AI MUST NEVER replace files.

The AI MUST NEVER generate backup files.

The AI MUST NEVER create "new_version", "copy", "final", "latest" files.

---

# Code Organization

Every file MUST have one clear responsibility.

The AI MUST NOT mix unrelated logic.

The AI MUST separate:

- UI
- Business Logic
- Data Access
- Validation
- Configuration

---

# Separation of Concerns

Business logic MUST remain independent from presentation.

Presentation MUST remain independent from database operations.

Database operations MUST remain independent from routing.

Configuration MUST remain independent from business logic.

The AI MUST NEVER violate separation of concerns.

---

# Modularity

Every module MUST be independent.

Every module MUST be reusable.

Every module MUST be replaceable without affecting unrelated modules.

The AI MUST NEVER tightly couple modules.

---

# Component Reuse

Before creating a new component, the AI MUST search for an existing one.

If an existing component can be reused, it MUST be reused.

The AI MUST NEVER duplicate UI components.

The AI MUST NEVER duplicate backend services.

The AI MUST NEVER duplicate helper functions.

---

# Dependency Rules

The AI MUST minimize dependencies.

Every dependency MUST have a clear purpose.

Unused dependencies MUST NEVER be introduced.

The AI MUST NEVER install packages automatically.

The AI MUST NEVER recommend packages without explicit approval.

---

# Technology Stack

The technology stack is fixed.

The AI MUST NOT replace any technology.

The AI MUST NOT introduce alternative frameworks.

The AI MUST NEVER migrate the frontend.

The AI MUST NEVER migrate the backend.

The AI MUST NEVER migrate the database.

---

# Production Readiness

Every generated implementation MUST be production ready.

Placeholder code is prohibited.

Mock implementation is prohibited.

Pseudo-code is prohibited.

Temporary implementation is prohibited.

Example implementation is prohibited unless explicitly requested.

---

# Naming Convention

The AI MUST follow existing naming conventions.

The AI MUST NEVER invent new naming styles.

Variable names MUST remain descriptive.

Function names MUST describe their behavior.

Class names MUST represent their responsibility.

---

# Consistency

Consistency is mandatory.

The AI MUST preserve:

- formatting
- spacing
- naming
- indentation
- architecture
- code style

The AI MUST NEVER mix styles.

---

# Scalability

Every implementation MUST support future expansion.

The AI MUST NEVER write code that blocks future scalability.

Hardcoded values MUST be avoided.

Magic numbers MUST be avoided.

Hardcoded paths MUST be avoided.

---

# Performance

The AI MUST always consider:

CPU usage

Memory usage

Database efficiency

Network efficiency

Rendering efficiency

The AI MUST NEVER perform unnecessary work.

---

# Maintainability

Every implementation MUST be understandable.

The AI MUST write code that another developer can easily maintain.

The AI MUST NEVER sacrifice readability.

---

# Reusability

Reusable logic MUST be extracted.

Duplicate logic MUST be avoided.

The AI MUST ALWAYS reuse existing implementations.

---

# Extensibility

Every module MUST allow future extension.

The AI MUST NEVER block future features.

---

# Documentation

The AI MUST document:

new modules

new architecture

new workflows

new services

new integrations

Documentation MUST remain synchronized with implementation.

---

# Breaking Changes

Breaking changes are prohibited.

The AI MUST preserve backward compatibility.

Breaking changes require explicit user approval.

---

# Backward Compatibility

Existing APIs MUST remain functional.

Existing URLs MUST remain functional.

Existing routes MUST remain functional.

Existing database relations MUST remain functional.

---

# Error Handling

Every error MUST be handled gracefully.

The AI MUST NEVER ignore exceptions.

The AI MUST NEVER suppress errors silently.

---

# Logging

Only meaningful events should be logged.

Sensitive data MUST NEVER be logged.

Passwords MUST NEVER be logged.

Tokens MUST NEVER be logged.

Session IDs MUST NEVER be logged.

---

# Configuration

Configuration MUST remain centralized.

Hardcoded configuration values are prohibited.

Environment-specific values MUST use configuration files.

---

# AI Restrictions

The AI MUST NEVER:

Assume requirements.

Guess business logic.

Invent APIs.

Invent routes.

Invent endpoints.

Invent controllers.

Invent database tables.

Invent columns.

Invent relationships.

Invent permissions.

Invent workflows.

Invent project requirements.

Invent validation rules.

Invent response formats.

Invent user interfaces.

Invent navigation.

Invent deployment strategies.

Invent architecture.

If required information is missing, the AI MUST stop and request clarification.

---

# Modification Rules

The AI MUST ONLY modify files requested by the user.

The AI MUST NEVER refactor unrelated code.

The AI MUST NEVER optimize unrelated files.

The AI MUST NEVER clean unrelated code.

The AI MUST NEVER rename unrelated symbols.

---

# Quality Standard

Every implementation MUST satisfy all of the following:

Correctness

Consistency

Readability

Maintainability

Security

Performance

Accessibility

Scalability

Production readiness

WITHOUT EXCEPTION.

---

# Final Rule

These architecture rules override all AI default behaviors.

If any AI behavior conflicts with these rules, these rules ALWAYS take precedence.

The AI MUST strictly follow this document before generating any code.
