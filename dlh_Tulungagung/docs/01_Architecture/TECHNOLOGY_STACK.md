# 1. Purpose

This document defines the official technology stack adopted by the Website Re-Engineering Project of Dinas Lingkungan Hidup Kabupaten Tulungagung.

The technology stack SHALL become the single authoritative reference for all frontend and backend development activities.

Any deviation from this specification MUST be documented through an approved Architecture Decision Record (ADR).

---

# 2. Scope

This specification governs:

- Backend Framework
- Frontend Framework
- Styling Strategy
- JavaScript Strategy
- Build System
- Asset Pipeline
- Database
- Development Environment
- Third-Party Libraries
- Deployment Compatibility

# 5. Frontend Technology Principles

## REQ-ARCH-001

The frontend SHALL use Laravel Blade as the only server-side rendering engine.

## REQ-ARCH-002

No Single Page Application framework SHALL be introduced.

Examples include:

- React
- Vue
- Angular
- Svelte
- Next.js
- Nuxt.js

## REQ-ARCH-003

Bootstrap SHALL provide the responsive grid and base component styling.

## REQ-ARCH-004

Tailwind CSS SHALL be limited to utility classes that improve layout consistency.

Tailwind SHALL NOT replace Bootstrap components.

## REQ-ARCH-005

Custom CSS SHALL implement the Eco-Government Design System.

---

# 6. JavaScript Strategy

The project SHALL prioritize lightweight interaction.

Approved APIs include:

- Intersection Observer
- Resize Observer
- Mutation Observer
- RequestAnimationFrame
- Fetch API

The following libraries are approved where justified:

- SwiperJS
- GLightbox
- AOS
- Lottie Web

jQuery MAY be used only when required by Bootstrap components.

No additional UI framework SHALL be introduced.

---

# 7. Styling Hierarchy

The styling cascade SHALL follow the order below:

1. Bootstrap Core
2. Bootstrap Utility Classes
3. Tailwind Utility Classes
4. Design Tokens
5. Component CSS
6. Page-specific CSS

Inline styles SHALL NOT be used except for dynamic values generated by the application.

---

# 8. Asset Strategy

The application SHALL maintain a centralized asset library.

Approved asset categories include:

- SVG Illustrations
- WebP Images
- PNG Transparent Assets
- Lottie Animations
- Icons
- Background Patterns
- Decorative Shapes

All production images SHOULD be optimized before deployment.

---

# 9. Responsive Support

The interface SHALL support:

- Desktop
- Laptop
- Tablet
- Mobile

The application MUST NOT produce horizontal scrolling under normal usage.

---

# 10. Accessibility

The frontend SHALL conform to WCAG 2.1 AA principles where technically feasible.

Minimum requirements include:

- Semantic HTML5
- Keyboard navigation
- Visible focus indicators
- Alternative text
- Accessible forms
- Sufficient color contrast
